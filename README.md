# 三粒度加工与差异分析联动系统

同一批业务数据有 **订单 / 订单行 / 分摊** 三种粒度，多份报表关联维度后计算指标。
本系统把 **粒度登记、加工执行器、差异分析服务** 三者联动起来，核心原则是：

> 错误关联必须被显式识别和拒绝，**绝不靠事后 `DISTINCT`/去重把错误结果"修"成正确值**。

不做通用数据库优化器，只针对这套虚构数据实现真实的加工、诊断与重建闭环。

## 1. 三条计算路径与适用条件

执行器对每张报表同时跑三条路径，后两者有严格准入条件，不满足即 `REJECTED` 并给出具体原因：

| 路径 | 做法 | 合法条件（全部满足） | 不满足时 |
|---|---|---|---|
| **NAIVE** 朴素明细连接 | 所有表连接后直接 `SUM`（诊断基线，永远执行） | —— | 用来**展示金额/计数为何被放大或丢失** |
| **ATJ** 先聚合再关联 | 先在事实粒度聚合，再逐表查找关联 | 路径上每条边都是 N:1、一端连接键**运行期唯一**、度量可加 | 拒绝：`FANOUT_EDGE` / `NON_UNIQUE_PARENT_KEY` / `NON_ADDITIVE_MEASURE` |
| **DJA** 明细连接按贡献归并 | 明细连接后按分摊权重折算每个副本，再聚合 | 每条扇出边都登记了**分摊基准**、每个父键下权重之和为 1、度量可加 | 拒绝：`MISSING_ALLOCATION_BASIS` / `INCOMPLETE_WEIGHTS` / `NON_UNIQUE_PARENT_KEY` |

关键区分：登记上的 N:1 不等于运行期安全。`dim_product` 出现重复 `product_id` 时，
名义 N:1 在运行期退化为一对多，引擎用运行数据做唯一性检查并拒绝，而不是相信登记。

## 2. 差异分析：两个方向都要看见

朴素连接的净差异会**掩盖**问题。本系统把净差异拆成两个独立量：

- **重复放大 `repeated_extra`（+）**：扇出使事实行被复制，同一金额被累计多次。
  逐行"重复贡献账本"定位到具体事实主键、副本数、单值 vs 重复累计、各落到哪些分组。
- **孤儿丢失 `lost_totals`（−）**：内连接丢弃无匹配事实行，度量被静默吞掉。

例：R4（行金额按营销活动，M:N 无基准）净额 −300，实际是 **重复 +600 与丢失 −900 抵消**。
只看净额会误判为"基本正确"，诊断把两侧同时报出。

## 3. 粒度登记与三服务联动

- `reg_tables` / `reg_columns`：每张表的粒度标签、粒度键、主键、列角色（键/维度/度量）与可加性。
- `reg_relationships`：表间关系的基数（N:1 / 1:N / M:N）、连接键、分摊基准、桥接表、启用状态。
- 网页修改关系（基数、启用/停用、基准）写入只增审计表 `reg_relationship_audit`；
  修改后执行器与诊断立即按新登记重新判定（测试 `TestRegistryLinkage` 覆盖）。
- M:N 关系登记 `join_through` 桥接信息，规划器展开为"左表→桥表→右表"两跳执行。

## 4. 任务只增，旧任务不可被修正版覆盖

- `report_jobs` 上有数据库触发器，**任何 UPDATE/DELETE 直接抛 `IntegrityError`**。
- 每次运行/重建都生成新 `job_id` 与自增 `version`。
- 重建在只增的 `job_supersessions` 记录 `旧任务 → 新任务`，旧任务内容原样保留。

## 5. 预置报表与故障场景

| 报表 | 场景 | 预期 |
|---|---|---|
| R1 行金额按品类 | 标准 N:1 | 三路径一致，结果=人工真值 |
| R2 订单金额按区域 | 维度在事实表 | 无连接，基线 |
| R3 分摊金额按成本中心 | 最细粒度直接聚合 | 三路径一致 |
| R4 行金额按活动 | 桥接 M:N 无基准 | ATJ/DJA 双拒；NAIVE 同时暴露重复与丢失 |
| R5 行金额按品类 | 开启重复维度 | 运行期键不唯一，双拒并给重复键样本 |
| R6 行金额按成本中心 | 带 weight 的 1:N | ATJ 拒扇出；DJA 合法且总量守恒(3300)；NAIVE 放大到 4850 |

故障开关：`duplicate_product`（产品维度重复行）、`incomplete_weights`（权重和=0.7 而非 1）。

## 6. 运行

```bash
pip install -r requirements.txt
# 启动 Web（默认 http://127.0.0.1:8000）
python -m app.web

# 测试（不依赖 flask，纯引擎+存储）
python -I -m unittest discover -s tests -v
```

控制台五个页签：① 粒度登记（可改关系、切故障、看审计）② 数据浏览
③ 三路径计算对比 ④ 差异诊断与重建 ⑤ 只增任务历史。

## 7. 目录

```
app/dataset.py   虚构订单/订单行/分摊/维度/桥接数据 + 人工核算真值
app/store.py     SQLite 存储、粒度登记、关系审计、只增任务表与触发器
app/engine.py    连接规划、NAIVE/ATJ/DJA 三路径、准入校验、贡献账本、差异分析
app/catalog.py   预置报表目录
app/web.py       Flask HTTP 边界
web/             原生 JS 诊断控制台
tests/           18 个单元/闭环测试
```
